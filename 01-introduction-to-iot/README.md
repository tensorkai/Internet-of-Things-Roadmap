# Introduction to IoT

[Back to roadmap](../README.md)

## Prerequisites

None. Start here.

## Topics to learn

- [ ] Trace the complete system: sensor, signal conditioning, controller, network, gateway, backend, application, and actuator. Identify which components are optional for a particular design.
- [ ] Compare device-to-device, device-to-gateway, and direct-to-backend architectures. Draw trust boundaries and explain behavior when each link fails.
- [ ] Explore home automation, agriculture, environmental monitoring, industrial monitoring, asset tracking, and wearables. Identify the physical measurement and user decision in each case.
- [ ] Write functional requirements and measurable limits for accuracy, latency, availability, battery life, installation cost, data retention, and support lifetime.
- [ ] Separate telemetry, events, commands, configuration, reported state, and desired state. A sent command is not proof that a physical action happened.
- [ ] Choose local versus remote responsibilities. Keep essential control behavior available during a network outage.
- [ ] Create an initial threat model, data inventory, and bill of materials. Include privacy, physical access, connectivity costs, and replacement work.

## Hands-on work

1. Draw a room-monitor architecture and annotate every arrow with data, direction, frequency, and failure behavior.
2. Write five testable requirements with numerical targets chosen for your project; state how each will be measured.
3. Compare two architectures against the same requirements and record the tradeoff.

## Completion evidence

- [ ] Explain the route from a physical measurement to a user decision and back to an actuator.
- [ ] Provide a system diagram, requirements table, initial risk list, and justified architecture choice.

Keep code, diagrams, measurements, and notes from these exercises with your project. Record failures and fixes, not just the successful demonstration.
